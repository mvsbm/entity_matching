# Reference data: sources, transformations, licences

These four files are **frozen snapshots**, each built once from public sources: `individual.json`, `companies.json` and `addresses.json` on 2026-10-28, `registry.json` on 2026-11-06. The downloads and the throwaway build environments were deleted afterwards; the steps below record exactly how each file was made. Each file is a JSON array with one record per line. The synthetic-data generator reads them (`er.generate.load_reference`, `load_registry`), for `scripts/generate.py`, `scripts/benchmark.py`, `scripts/choose_kind.py`, the demo and the tests. Every run reads two of them, `individual.json` and `registry.json`: they train the name model that tells persons from companies (`er.kind.name_model`), on one half of them (`er.generate.name_model_split`), and the cached model is checked against them.

## individual.json: 60,000 persons

- **Source:** NVIDIA **Nemotron-Personas-Japan**, `data/train-00000-of-00008.parquet` (shard 1 of 8). https://huggingface.co/datasets/nvidia/Nemotron-Personas-Japan
- **Licence: CC BY 4.0.** Attribution: "Nemotron-Personas-Japan, NVIDIA, licensed under CC BY 4.0." The names were generated by NVIDIA from name lists sourced from Myoji-Yurai.net; they are synthetic personas, not real people.
- **Transformation:**
  1. The dataset has no name field. Names are parsed from the start of the `persona` text with the regex `^([^\s、。,]{1,5})[ 　]([^\s、。,]{1,5}?)は` (e.g. `野本 花代子は…`). 122,257 of ~125k rows matched.
  2. Kana readings come from **SudachiPy 0.7.0 + sudachidict-core 20261015** (Apache-2.0), split mode C. Each name part is read separately.
  3. A row is kept only if both readings are pure katakana. The first 60,000 such rows are kept, with `sex`, `age` and `prefecture` from the dataset.
- **Fields:** `surname, given, surname_kana, given_kana, sex, age, prefecture`.
- **Caveat:** machine readings of given names can differ from the intended reading. Each kanji spelling always gets the same reading.

## companies.json: 31,596 companies

- **Source:** **Wikidata** SPARQL (https://query.wikidata.org). Licence: **CC0 1.0**, no attribution required.
- **Query,** run once per direct company type:
  `?c wdt:P31 wd:<type> ; wdt:P17 wd:Q17 ; rdfs:label ?label (lang "ja") ; OPTIONAL wdt:P1814 ?kana`
  The types: Q4830453 business, Q783794 company, Q891723 public company, Q1480166 kabushiki gaisha, Q6881511 enterprise, Q85907346 rail company (Japan), Q10438042 bus company, Q2085381 publishing house, Q210167 video game developer, Q5354754 talent agency, Q1616075 television station, Q1064063 private railway, Q11086540 third-sector railway, Q96888669 academic publisher, Q1589009, Q167037, Q18388277, Q1331793, Q22687, Q740752, Q1762059, Q1631129, Q936518. That gives 35,711 distinct items.
  Direct types are used on purpose. The transitive class tree (`wdt:P31/wdt:P279* wd:Q783794`) is dominated by Japanese municipalities: 13,766 "dissolved municipalities of Japan" plus cities, towns and villages.
- **Transformation:**
  1. Legal forms (株式会社, 有限会社, 合同会社, 合資会社, 合名会社, (株), ㈱, (有)) are stripped from the start and end of the label, and the kana equivalents from the reading. The generator adds legal forms itself.
  2. Organisations that are not companies are dropped: labels containing 組合, 局, 通り, 商店街, 協会, 連合会, 公社, 機構, 事業団, 財団, 学校, 大学 or 病院.
  3. Kana: the official kana name (P1814) when present (1,177), converted from hiragana to katakana; otherwise the Sudachi reading of the label (30,419). `kana_source` records which one.
  4. A record is kept only if its kana is pure katakana and at least 2 characters long. Records are de-duplicated on kana.
- **Fields:** `name, name_kana, kana_source, wikidata_id`.

## addresses.json: 46,364 towns (all 47 prefectures)

- **Towns:**
  - **Source:** **geolonia/japanese-addresses** `latest.csv` (https://github.com/geolonia/japanese-addresses; data frozen 2023-11; the project continues as japanese-addresses-v2, which has no kana).
  - **Licence: CC BY 4.0.** Attribution: "Japanese Addresses by Geolonia, CC BY 4.0". It is derived from MLIT 位置参照情報, Japan Post and other open data.
  - **Content:** prefecture, city and town names with kana, plus the 5-digit municipality code.
- **Postal codes:**
  - **Source:** **yubinbango/yubinbango-data** (https://github.com/yubinbango/yubinbango-data, `gh-pages` branch, updated 2026-10). It maps each postal code to (prefecture code, city, town) and is derived from Japan Post's postal code data.
  - **Licence:** the repository declares no licence on GitHub. Japan Post states its postal code data may be used freely.
- **Transformation:**
  1. Town names are split into 大字 and 丁目, e.g. `旭ケ丘一丁目` → town `旭ケ丘`, chome 1; kanji numerals become integers. The trailing digits are dropped from the town kana.
  2. Postal codes are joined on (prefecture code, city, town with any `（…）` removed); the first postal code wins. yubinbango writes prefecture codes without a leading zero (`1`), so they are zero-padded to geolonia's `01`.
  3. Towns without a town-level match are dropped: 233,679 of 277,630 had one.
  4. At most 1,000 towns are sampled per prefecture (seed 0).
- **Fields:** `pref, pref_kana, city, city_kana, city_code, town, town_kana, chome (int or null), postal`.

## registry.json: 60,000 corporations

- **Source:** the National Tax Agency's corporate-number publication site, 法人番号公表サイト, full data (全件データ), CSV Unicode, all of Japan, created 2026-10-30. https://www.houjin-bangou.nta.go.jp/download/zenken/
- **Licence: Public Data License 1.0** (公共データ利用規約 第1.0版), compatible with CC BY 4.0. Attribution, as the site's terms ask: 「出典：国税庁法人番号公表サイト（国税庁）（https://www.houjin-bangou.nta.go.jp/）を加工して作成」. This file is processed data: it is not the National Tax Agency's, and no government body made it.
- **Transformation:**
  1. Of 5,850,621 rows, those with a reading (フリガナ) are kept, government bodies (法人種別 101 and 201) dropped, and rows de-duplicated on (reading, prefecture): 2,851,033.
  2. Each name's legal form is found in the name (longest first, so 医療法人社団 before 医療法人), with whether it leads the name (株式会社〇〇) or ends it (〇〇株式会社). The reading never holds 株式会社, 有限会社 or 合同会社; a leading legal form's reading is removed where one does (some 特定非営利活動法人).
  3. Readings that are not 2 or more katakana are dropped. 35,000 corporations of Miyagi (04) and Okayama (33) and 25,000 of Fukuoka (40) are sampled (seed 0); `scripts/choose_kind.py` trains on the first two prefectures and tests on the third.
  4. Each row gets its legal form's reading and its bank abbreviation (the Zengin list: 株式会社 カ, 有限会社 ユ, 医療法人 イ, …); none for a name without a legal form.
- **Fields:** `reading, legal, abbreviation, front, prefecture`.
